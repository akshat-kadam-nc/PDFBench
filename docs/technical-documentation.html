Architecture

PDF Bench is a local full-stack app wrapped as a desktop window. Three layers:

LayerTechnologyRole
Desktop shellpywebview + Edge WebView2Native window that displays the UI; no browser, no console.
Local serverFastAPI on Uvicorn (background thread)Does the PDF work; serves the UI and a small JSON API on 127.0.0.1.
FrontendReact (via CDN) in a single index.htmlThe tabbed UI, rendered inside the native window.

The whole thing is bundled by PyInstaller into one PDFBench.exe, and that exe is wrapped by an Inno Setup installer.

Request flow

Start Menu → PDFBench.exe
  └─ desktop.py
       ├─ picks a free port (8765+)
       ├─ starts Uvicorn(FastAPI app) on a daemon thread
       └─ opens a WebView2 window at http://127.0.0.1:<port>
            └─ index.html (React) ── fetch() ──▶ /api/* endpoints
                                                    └─ *_core.py (PyMuPDF / pypdf)

Closing the window ends the process; the daemon server thread is torn down with it.

The text-layer invariant

The searchable text layer is never rasterized. This is the core correctness rule, because the output feeds text-extraction / RAG pipelines.
  • Deskew applies a pypdf page rotation transform — the page's content stream and text are untouched; only the visual angle changes.
  • Compress replaces the embedded page image with a smaller re-encoded image (extract → JPEG draft-decode → resize → recompress). The text layer sits above the image and is left alone.
  • Merge / Organize are structural pypdf operations (copy pages, set /Rotate), so text is copied verbatim.

Frontend & state

The UI is one React tree (Babel-in-browser, no build step). Key ideas:

  • Working document lives in top-level state as a File. Each tool sends it to an endpoint and replaces it with the result (a new File built from the response blob), so operations chain with no re-upload.
  • Pipeline selection is on the tabs: Deskew/Compress carry checkboxes; one Run sends both flags to /api/process in one call.
  • Preview is a persistent right-hand column; it uses WebView2's built-in PDF viewer via an <iframe> pointed at an object URL, so switching tabs doesn't reload it.
  • Theme is CSS custom properties toggled via a data-theme attribute, defaulting to the OS preference and persisted in localStorage.

File & memory handling

  • In-memory processing. Uploads are read into memory (bytes) and each stage passes bytes to the next; results are streamed straight back in the HTTP response. Source files on disk are never modified.
  • Size guard. Every upload is checked against MAX_UPLOAD_MB (default 80 MB) and rejected with a clear error if larger.
  • Memory hygiene. Large intermediates are released and gc.collect() is called between deskew and compress. MemoryError is caught and returned as a friendly 507 rather than crashing.
  • Thumbnails are rendered at ~20% scale and returned as base64 data URLs, kept only for the current Organize session.
  • Frozen-exe unpack. As a PyInstaller one-file build, the exe unpacks to a temp directory on each launch (the ~15–20s first-start cost) and the bundled web/ is resolved from that path.
  • Downloads. Handled by WebView2 (enabled explicitly in desktop.py); the browser layer writes the file, the Python side never persists outputs.

Data & storage

The log is append-only (one JSON object per line) so each write is O(1) and prior data is never rewritten; it lives outside the install directory and survives reinstalls.

Packaging & installer

Executable — build_exe.bat runs PyInstaller with --onefile --windowed --icon assets\PDFBench.ico, collecting the heavy native libs (scikit-image, scipy, PyMuPDF, deskew, pywebview) and bundling web/. Output: dist\PDFBench.exe (~120 MB).

Installer — installer\PDFBench.iss (Inno Setup) packages that exe into installer\Output\PDFBench-Setup.exe. It installs per-user (no admin), creates Start Menu and optional desktop shortcuts, and registers an uninstaller. The exe is unsigned, so Windows SmartScreen warns once on first run.

Build from source

run.bat            # dev: create .venv, run the server in a browser
build_exe.bat      # build dist\PDFBench.exe (windowed one-file)
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\PDFBench.iss   # installer

Requires Python 3.11 and (for the installer) Inno Setup 6 on the build machine only. The .venv, build/, dist/, *.spec, and installer/Output/ are regenerated, not committed.

Limits & notes

  • Single-file upload limit: 80 MB (MAX_UPLOAD_MB).
  • The app is Windows-only as packaged (WebView2 + Inno Setup); the Python app itself is cross-platform.
  • A Dockerfile and render.yaml remain from an abandoned cloud-hosting experiment; the shipping path is the local desktop app.
  • No code signing; distribute with a checksum and expect the SmartScreen prompt.
